# Use openid-client for Operator authentication

The Bun-only operator surface will use exactly pinned `openid-client` 6.8.7 for OIDC discovery, confidential Authorization Code plus PKCE, verified ID-token claims, and end-session URL construction. Gateway-owned modules retain the fixed routes, one-use five-minute login attempts, `(issuer, subject)` Operator Identity projection, group policy, and opaque Operator Sessions; `oidc-provider` 9.11.3 is test-only and runs in a Node child for deterministic Pocket-ID-like and Authentik-like contract profiles.

Better Auth 1.7.2 is rejected because its built-in model conflicts with mandatory behavior: it gives OAuth state a ten-minute lifetime and consumes it non-atomically, requires email-centered users and fallback linking, persists provider tokens, exposes a broader route model, lacks independent idle/absolute expiry and both session caps, and cannot atomically create the identity and session through Bun SQLite. Its measured feature-import proxy was also materially larger than the selected protocol module. The complete evidence is recorded in [the issue 22 research note](../../research/issue-22-oidc-session-selection.md).

This decision supersedes only ADR 0023's three-package workspace runtime ceiling by adding `openid-client` as a fourth, Bun-only dependency. The Worker continues to contain only its pre-existing Drizzle, `jose`, and Zod graph, enforced by a normalized source-map guard.

No provider token or raw claim is retained. Local Operator Session revocation is therefore the only guaranteed logout behavior; a discovered provider logout without an ID-token hint is best effort and cannot promise a portable post-logout return for both Pocket ID and Authentik. The production administration database, routes, cookies, and isolation composition remain owned by the separate Bun administration-foundation decision and implementation.
