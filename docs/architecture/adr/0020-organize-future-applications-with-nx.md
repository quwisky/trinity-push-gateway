# Organize future applications with Nx

The repository will use an Nx 23 workspace with root-managed pnpm dependencies. The existing Cloudflare Worker and Bun deployment remain one `push-gateway` application under `apps/push-gateway` because they implement one Push Gateway contract and release together. A tracked `apps/push-gateway-ui` placeholder reserves the name and location of a future Angular administration application without introducing Angular dependencies, project metadata, an administration API, authentication design, or UI code.

Official Nx ESLint and Vitest plugins infer project-scoped `lint` and run-mode `test` targets. Nx Core exposes explicit targets for Wrangler, Bun, TypeScript, migration, coverage, bundle-policy, and aggregate commands because the specialized plugins are absent, deprecated, or do not preserve the runtime contract. Deterministic validation and filesystem build outputs use the local Nx cache; fixing lint, development servers, migrations, deployment, releases, and Docker-daemon state do not. CI uses affected execution immediately, keeps required check names visible as successful no-ops when the gateway is unaffected, and treats shared dependencies, workspace configuration, Compose, and CI configuration as gateway-affecting. Nx Cloud, Nx Release, Nx Docker, and premature Angular integration remain excluded; Release Please continues to own versioning, changelog generation, tags, and stable releases.

Gateway-owned source, tests, migrations, runtime configuration, and the Dockerfile live within `apps/push-gateway`. The root retains workspace tooling, root-managed dependencies, Compose, CI, documentation, and release configuration. Build artifacts live under `dist/apps/push-gateway`, coverage under `coverage/apps/push-gateway`, and internal gateway imports remain relative. This structure creates a real future application boundary without splitting the Worker and Bun adapters into artificial projects.
