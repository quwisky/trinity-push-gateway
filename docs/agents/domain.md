# Domain docs

This repository uses a single-context domain-document layout.

## Before exploring

Read the following when relevant:

- `CONTEXT.md` for the project glossary and domain boundaries.
- Relevant ADRs under `docs/adr/`.

If either location is absent, proceed without treating its absence as an error.

## Vocabulary

Use the terms defined in `CONTEXT.md` in issues, specifications, tests, implementation plans, and code. Avoid synonyms that the glossary explicitly rejects.

When a necessary concept is missing, reconsider whether existing vocabulary covers it. If it is genuinely new, record it through the domain-modeling workflow.

## Architecture decisions

Surface conflicts with existing ADRs explicitly. Do not silently override an accepted architectural decision.
